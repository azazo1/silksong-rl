# Boss 强化学习训练设计

这套东西由两部分组成:

- `mods/rl-env`: 游戏内插件, 负责观测采集, 动作注入, 回合编排与通信.
- `trainer/`: Python 侧, 负责环境封装, 奖励计算与 PPO 训练.

两者用本机 TCP 上的一条长度前缀二进制协议通信, 奖励与算法完全在 Python 侧, 因此调整训练
不需要重编插件, 调整采集内容才需要.

## 数据流

```
Python 训练进程                         游戏进程 (RLEnv 插件)
  reset()  ──── Reset 命令 ───────────►  载入 Boss 存档 → 同场景重载 → 等就绪
           ◄─── Observation (episode_start) ──
  act(a)   ──── Step 命令 (4 个 int32) ─►  覆写 HeroActions → 放开 N 个物理帧
           ◄─── Observation (值 + 终止标志) ───
  ...                                      ...
  终止后回到 reset()                       等下一个 Reset
```

## 观测

字段表由 `mods/rl-env/src/Observation/ObservationSchema.cs` 唯一定义, 连接时通过 `Hello`
消息发给 Python, 训练侧按名字取值. 当前字段分四组:

| 组 | 内容 |
| --- | --- |
| 主角 | 归一场地坐标, 世界坐标, 速度, 朝向, 是否在地面, 血量与比例, 丝比例, 无敌/攻击/受击/死亡标志 |
| Boss | 存活, 相对主角的归一化位移, 速度, 朝向, 血量与比例, 血量上限, 距离, 状态机 id |
| 场地 | 场地中心与半宽半高 (回合开始时抓一次, 回合内不变) |
| 事件与时间 | 物理帧号, 回合 step 序号, 本步造成伤害, 本步受到伤害, Boss 击杀, 主角阵亡 |

设计取舍:

- 坐标归一化用回合开始时固定的场地矩形, 不用实时相机视野, 否则相机会跟着主角动, 观测非平稳.
- Boss 的动作阶段用"所有 FSM 的 `FSM名=状态名` 拼成一个键"再映射到整数 id, 新状态通过
  `StateMap` 消息增量同步给 Python. 这样既不需要预先知道某个 Boss 有哪些状态, 也能事后
  从映射里还原出可读的状态名.
- 原始值 (世界坐标, 速度, 血量) 一并发送, Python 侧用 `VecNormalize` 归一化, 便于改观测尺度.

## 动作

`MultiDiscrete([3, 3, 2, 2])` = `[左右, 上下, 跳跃, 攻击]`. 一个 step 内按键保持按住,
与真人握手柄一致; 想让跳跃/攻击这类边沿动作再次触发, 必须让下一步把按键松开. 这样跳跃的
可变高度 (松手把上升速度砍半) 与蓄力这类按住语义都保持原样.

攻击方向由"上下"与主角朝向共同决定 (上劈 / 前劈 / 下劈), 与游戏输入层一致; 主角朝向由左右
输入改变, 所以"朝哪边打"是左右加攻击的组合, 不需要单独的方向维度.

## 步进时序

1. Python 发 Step, 插件在当前物理帧末采样随机状态之前先把动作写入虚拟输入面板;
2. 时间倍率从 `IdleTimeScale` 提到 `Speed`, 让世界开始推进;
3. 计数 `StepFrames` 个物理帧 (采样点挂在 `CustomPlayerLoop` 的 super-late fixed update,
   保证伤害与死亡已经结算);
4. 到点或出现终止事件, 就把时间倍率压回 `IdleTimeScale`, 采样观测并发给 Python.

不用 `Time.timeScale = 0` 做暂停: 那会让 `FixedUpdate` 与游戏协程整体停摆, 场景载入这类
协程会永久挂起. 改用极小非零倍率 (`IdleTimeScale`), 世界几乎不动但仍然是活的.

训练期间还会屏蔽 `GameManager.FreezeMoment` 顿帧, 否则受击/击杀插进来的顿帧会把
"一个 step 等于固定帧数" 这个前提打乱.

## 回合重置

只有重载场景能让被销毁的 Boss, 弹幕与场地物件回到初始状态, 因此重置原语就是"换一份干净的
存档数据 + 发起一次同场景重载". 具体步骤与坑见 `mods/rl-env/README.md` 的"工作方式"一节,
其中最关键的是重置窗口内必须屏蔽 `GameManager.SaveLevelState()`, 否则旧场景的持久化项会把
新数据写脏, 表现为新场景里 Boss 隐形且战斗不触发.

## 奖励

奖励在 `trainer/src/silksong_rl/reward.py` 里算, 输入是相邻两帧观测. 默认项:

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 造成伤害 | +1.0 / 点 | 来自插件对 `HealthManager.Hit` 的 hp 前后差, 已过游戏自身的伤害缩放 |
| 受到伤害 | -1.0 / 次 | 订阅 `HeroController.OnTakenDamage`, 只在确认扣血时触发 |
| 击杀 Boss | +25 | |
| 自己阵亡 | -25 | `OnDeath` 与 `OnHazardDeath` 都订阅 |
| 每步 | -0.002 | 鼓励速战 |
| 接近 Boss | 0 (可选) | 按归一化距离的减少量给奖励 |

## 游戏内联调清单

代码是按反编译结论写的, 但下面这些必须在游戏里实测确认 (来自 `.tmp/research/03-reset.md`
的清单, 按重要性排序):

1. 打完 Boss 后重置, 新回合 Boss 是否正常出现并开打 (持久化项污染).
2. 重置后 `GameManager.GetSceneNameString()` 是否等于目标场景 (落点 marker 是否有效).
3. 重置期间 `SceneData.PersistentBools` 是否又被写入了 Boss 的死亡项 (屏蔽是否生效).
4. 连续重置 20 次以上: 场景对象是否重复/缺失, 内存是否持续上涨.
5. 5 号槽位与真实存档 0-4 的隔离: 训练前后比对 `user0..4.dat` 的哈希.
6. 每回合耗时分解: 场景切换, Boss 出现, 空转帧各占多少.
7. 观测是否自洽: 用手动动作验证速度/血量/伤害事件与画面一致.
